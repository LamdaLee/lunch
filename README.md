# 런치패스

AX·SF·AX2기·DM 및 교수·강사·운영진을 위한 점심 예약 웹앱입니다. 식당별 방문 예정 인원을 배분하고, 식당은 전용 링크에서 인원과 예약 정원을 관리합니다. 종이 식권은 그대로 사용하며 결제·식사 금액 입력·정산 기능은 포함하지 않습니다.

## 현재 Vercel 배포

- 공개 주소: https://matzip-lamda7.vercel.app
- Vercel 프로젝트: `lamda7/matzip`
- 데이터베이스: Neon `lunchpass-db`, `free_v3` 무료 플랜, 싱가포르 지역
- Production의 `DATABASE_URL`은 Neon 통합으로 연결되어 있습니다.
- 최초 관리자 설정 키는 이 클라우드의 `.local/production-setup-key.txt`에 별도로 보관되어 있으며 Git 및 배포 파일에 포함하지 않습니다. 공개 페이지의 최초 관리자 설정에서 키와 본인이 사용할 ID·비밀번호를 입력합니다.
- 앱의 로그인은 학생과 식당을 위한 것이므로 Production 주소는 Vercel 계정 없이 접속하도록 설정했습니다. Preview와 고유 배포 URL은 Vercel 인증으로 보호합니다.
- 현재 배포는 CLI로 수행했습니다. GitHub `LamdaLee/test` 연결은 기존대로 유지하며, 현재 Production Branch는 `main`입니다. 이번 소스는 `codex/lunchpass` 브랜치에 있으므로 변경을 반영하려면 CLI로 다시 배포하거나 Vercel에서 Production Branch를 변경해야 합니다.

## 운영 규칙

- 시간대는 항상 **한국 시간(Asia/Seoul)** 기준입니다.
- 매일 **09:00 이상, 12:00 미만**에 예약·변경·취소할 수 있습니다. 12:00 정각부터 마감입니다.
- 식사 시간은 모든 식당이 **12:50–14:00**입니다.
- 1인당 하루 한 식당을 예약합니다. 식당 변경은 기존 예약을 함께 변경하며, 변경 실패 시 기존 예약이 유지됩니다.
- 교수·강사·운영진도 동일한 규칙을 적용합니다.
- 예약 정원은 식당이 정합니다. 정원은 다음 날에도 유지되며 휴무일에는 접수를 중단합니다. 이미 예약된 당일 인원보다 정원을 줄일 수 없습니다.
- 예약은 방문 예정 인원이며 좌석 확정이나 실제 방문을 보장하지 않습니다. 예약 마감 후 식당 사정으로 식사가 불가능해지면 운영진이 이용자에게 직접 안내해야 합니다.
- 종이 식권 지원 한도는 11,000원입니다. 초과 금액은 이용자가 식당에서 직접 결제합니다. 이 앱은 정산 자료가 아닌 예약 자료를 제공합니다.

## 포함된 기능

- 학번/로그인 ID와 비밀번호로 로그인, 첫 로그인에서 비밀번호 변경 강제
- 이름·학번·반 등록, 여러 명 일괄 등록 및 초기 비밀번호 CSV 다운로드
- 개인별 초기 비밀번호 자동 생성 또는 운영진이 지정한 초기 비밀번호
- 동명이인 지원, AX·SF·AX2기·DM 및 새로운 반 추가
- 식당 등록·안내·정원·접수 상태 관리
- 식당 전용 링크, 인원 및 반별 집계, 식당이 직접 정원·접수 상태 설정
- 하루 한 건 예약, 취소, 식당 변경, 정원 초과 방지
- 카드형 게시판, 운영 공지 상단 고정, 본인/관리자 게시글 삭제
- 날짜별 운영 현황·예약자 명단·CSV 다운로드
- 사용자 비밀번호 변경, 운영진의 비밀번호 초기화, 식당 링크 재발급
- 모바일과 PC 대응, Pretendard 폰트 자체 제공

등록된 식당: 복록수, 조선명가, 3일소고기국밥, 7930 손님식탁, 칼국수 만드는 사람들, 마마김밥, 교반, 오류동 꼬마김밥, 파스토보이. 처음에는 **정원 0명·접수 중단**입니다. 운영진이 각 식당에 전용 링크를 전달하고 식당이 정원과 접수 여부를 저장하면 예약할 수 있습니다.

## 로컬 실행

Node.js **24.x**가 필요합니다. 기존 체크아웃을 사용합니다. 별도 Git worktree를 만들 필요가 없습니다.

```bash
cd /workspace/test
npm ci --cache .local/npm-cache
npm run setup
npm start
```

`npm run setup`에서 관리자 이름, 로그인 ID(기본 `admin`), 비밀번호를 지정합니다. 비밀번호는 터미널에서 숨겨 입력하고 해시로 저장합니다. 관리자도 최초 로그인 시 비밀번호를 변경합니다. 서버 기본 포트는 3000이며 `PORT`로 변경할 수 있습니다.

로컬 개발은 `.local/lunchpass.sqlite`에 데이터를 저장합니다. `.local`은 Git에 포함되지 않습니다. 개발 서버 종료 후에도 파일은 남지만, 이 파일을 삭제하면 계정과 예약이 사라집니다.

## Vercel 배포

Vercel 기본 주소 `프로젝트명.vercel.app`을 사용할 수 있어 별도 도메인 구매가 필요 없습니다. Vercel에서 SQLite 파일은 영구 저장소로 사용할 수 없으므로 **PostgreSQL 연결이 필수**입니다.

### 1. 소스 배포

소스는 GitHub의 **`LamdaLee/test` → `codex/lunchpass` 브랜치**에 있습니다. Vercel의 **New Project → Import**로 저장소를 가져오고, 프로젝트의 **Settings → Git → Production Branch**를 `codex/lunchpass`로 설정한 뒤 해당 브랜치를 배포합니다. 기존 `main`에는 앱 코드가 없으므로 브랜치를 확인하세요. 또는 배포용 ZIP을 풀고 해당 디렉터리에서 Vercel CLI의 `npx vercel`을 사용합니다.

- Framework Preset: **Other**
- Node.js: **24.x**
- Build Command: `npm run build` (저장된 `vercel.json` 사용)
- Output Directory: `public`
- Install Command: `npm ci`

`vercel.json`이 정적 화면과 Node.js API의 경로를 연결합니다. `/api/*`는 서버 함수로, `/restaurant`는 식당 화면으로 연결합니다.

### 2. 데이터베이스 연결

Vercel의 Storage/Marketplace에서 **Neon PostgreSQL**을 생성하고 프로젝트에 연결하거나 기존 PostgreSQL을 사용합니다. 제공자 화면에서 연결 문자열을 확인해 프로젝트의 Environment Variables에 **`DATABASE_URL`**로 저장합니다. 통합이 다른 이름으로 변수를 생성했다면 `DATABASE_URL`을 별도로 설정합니다.

Neon의 **pooled connection** 문자열을 권장합니다. 제공자의 TLS 설정을 유지하며, `sslmode=require`는 애플리케이션에서 인증서까지 검증하는 `verify-full`로 적용합니다. 인증서 검증을 끄지 않습니다. 앱은 최초 요청에서 필요한 테이블·반·식당을 자동으로 생성합니다.

### 3. 최초 관리자 설정

Environment Variables에 **`SETUP_KEY`**를 추가합니다. 비밀번호 관리자 등으로 생성한 **24자 이상의 충분히 긴 무작위 값**을 사용하세요. 이 값은 최초 관리자 계정 생성을 보호하는 키입니다. 실제 데이터베이스 주소·비밀번호·설정 키를 Git이나 채팅에 붙여 넣지 마세요.

Production에 변수를 저장하고 **Redeploy**합니다. Preview에서도 테스트하려면 실제 학생 데이터와 분리된 테스트 데이터베이스를 연결하세요. Production과 Preview에 같은 학생 데이터베이스를 연결하지 않는 것이 좋습니다.

배포된 페이지를 열어 **최초 관리자 설정**을 누르고 설정 키, 관리자 이름, 로그인 ID, 비밀번호를 입력합니다. 관리자 생성은 한 번만 가능하며, 완료 후 Vercel에서 `SETUP_KEY`를 삭제하고 다시 배포해도 됩니다. Vercel에서는 로그인 쿠키가 자동으로 `Secure` 설정됩니다.

### 4. 운영 준비

1. 관리자로 로그인해 운영 관리 화면을 엽니다.
2. 각 식당의 **식당 링크**를 복사해 해당 식당에만 전달합니다. 링크 소유자는 정원·접수 여부를 변경할 수 있으므로 전체 학생에게 공유하지 않습니다.
3. 식당이 최대 인원을 입력하고 **예약 접수하기**를 선택해 저장합니다.
4. 이용자 등록에서 이름·학번·반을 입력합니다. 일괄 등록 형식은 한 줄에 `이름,학번,반`입니다.
5. 발급된 초기 비밀번호는 당사자에게만 전달합니다. 전체 계정 CSV를 학생에게 공유하지 않습니다. 학생은 첫 로그인에서 자신의 비밀번호로 변경합니다.
6. 오전 9시부터 예약하고, 낮 12시 이후 식당 전용 페이지에서 확정된 방문 예정 인원을 확인합니다.

식당 링크가 유출되면 운영 관리에서 재발급합니다. 이용자가 비밀번호를 잊으면 운영진이 초기화하고 새 초기 비밀번호를 전달합니다.

### 5. 공개 배포 후 확인

- 관리자로 로그인할 수 있는지 확인합니다.
- 테스트 학번을 등록하고 초기 비밀번호로 로그인 → 새 비밀번호 변경 → 예약 화면 접근을 확인합니다.
- 식당 전용 링크에서 정원 저장·인원 확인이 되는지 확인합니다.
- 09:00–12:00 사이 실제 예약·변경·취소를 확인합니다. 그 외 시간에는 마감/개시 전 상태가 정상입니다.
- 데이터베이스 제공자의 백업·복구 설정을 확인합니다. 앱의 예약자 CSV는 전체 데이터베이스 백업을 대체하지 않습니다.

## 검증

```bash
npm test
npm run build
npm run test:browser
```

브라우저 테스트는 Chromium이 필요합니다. 이 환경에서는 `/usr/bin/chromium`을 사용합니다. 다른 컴퓨터에서는 `CHROMIUM_PATH`에 실행 파일 경로를 지정합니다.

PostgreSQL 검증은 **테스트 전용 데이터베이스**를 `TEST_DATABASE_URL` 환경 변수로 지정한 뒤 `npm test`를 실행합니다. 테스트가 별도 임시 스키마를 만들고 삭제하므로 Production 연결 문자열을 사용하지 않습니다. PostgreSQL을 지정하지 않은 로컬 테스트에서는 여러 서버 인스턴스에 대한 PostgreSQL 전용 테스트 한 건을 건너뜁니다.

한국 시간 예약 개시·마감, 동시 예약 정원, 변경 실패 시 기존 예약 보존, 권한, 첫 비밀번호 변경, 식당 자체 정원 설정, 반 추가, 재시작 후 보존, Vercel 요청 형태, 게시판 텍스트 처리 등을 검증합니다. 공개 Vercel 배포는 계정과 실제 `DATABASE_URL`을 연결한 후 별도로 검증해야 합니다.

## 프로젝트 구성

- `public/`: 화면, 스타일, 브라우저 코드, 폰트
- `server.js`: 로컬 HTTP 서버 및 API
- `lib/store.js`: SQLite/PostgreSQL 저장소·트랜잭션·비밀번호·한국 시간 처리
- `api/index.js`, `vercel.json`: Vercel 서버 함수와 배포 설정
- `setup.js`: 로컬 최초 관리자 생성
- `test/`, `e2e/`: 서버 및 브라우저 검증
